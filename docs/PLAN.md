# PLAN.md — 패킷 길찾기 (방화벽 정책 시뮬레이터) 구현 계획

> 판정 규칙의 기준은 SPEC.md 이다. 이 문서는 데이터와 구조, 단계만 정한다.
> 확정 사항: **브라우저 단독 앱(순수 JavaScript ES 모듈, 서버·빌드·의존성 없음)**, 구역 CIDR 은 아래 1-1 값 그대로.
> 개발 환경이 Node 12(npm 없음)라 TypeScript/Vite 는 쓰지 않는다. 테스트는 Node 내장 `assert` 로 `.mjs` 파일을 실행한다.

## 1. 입력 데이터 (SPEC 2절이 참조하는 절)

### 1-1. 구역 4개
| 구역 | CIDR | 비고 |
|---|---|---|
| 인터넷 | 아래 세 사설 구역에 속하지 않는 모든 IP | 예: 203.0.113.10 |
| DMZ | 172.16.10.0/24 | 웹·메일 서버 |
| 내부망 | 10.10.0.0/16 | 업무 PC, DB, SIEM |
| 개발·운영 서버망 | 10.20.1.0/24 | 운영·개발 서버 |

### 1-2. 호스트 (예제 데이터, SPEC 에 고정된 값은 10.20.1.20, 203.0.113.10 뿐)
| 이름 | IP | 구역 |
|---|---|---|
| 웹서버 | 172.16.10.10 | DMZ |
| 메일서버 | 172.16.10.20 | DMZ |
| 관리자 PC | 10.10.1.10 | 내부망 |
| DB 서버 | 10.10.2.10 | 내부망 |
| SIEM | 10.10.3.10 | 내부망 |
| 운영 서버 | 10.20.1.10 | 개발·운영 서버망 |
| 개발 서버 | 10.20.1.20 | 개발·운영 서버망 |
| 외부 사용자 | 203.0.113.10 | 인터넷 |

### 1-3. 주소 그룹
| 그룹 | 구성 |
|---|---|
| 외부망 | 구역 인터넷 |
| DMZ 웹서버 | 웹서버 |
| 내부망 DB 서버 | DB 서버 |
| 내부망 관리자 PC | 관리자 PC |
| 개발·운영 서버 | 운영 서버, 개발 서버 |
| 보안관제(SIEM) | SIEM |
| 내부 장비·DMZ | 구역 내부망, 구역 DMZ |

### 1-4. 규칙 형식
`{ no, src, dst, service[], action: allow|deny, purpose }`
- src/dst: `Any` | 구역 이름 | 주소 그룹 이름 | 단일 IP
- service: `{ proto: TCP|UDP, ports: [단일 또는 범위] }` 목록, 또는 `Any`
- 기본 정책표 = SPEC 1-2 의 5행

## 2. 구조

```
fw_simulator/
├─ SPEC.md, docs/PLAN.md
├─ src/core/            # DOM·I/O 비의존 순수 함수
│  ├─ topology.js       # 구역·호스트·그룹, IP→구역 (CIDR)
│  ├─ parse.js          # 주소·서비스 파싱과 검증 (SPEC 2-7)
│  ├─ matcher.js        # first-match 판정 (2-1)
│  ├─ analyzer.js       # covers, 기본 거부, 섀도잉, 중복, syslog (2-2~2-4, 2-6)
│  ├─ policy.js         # 규칙 추가·수정·삭제·이동
│  └─ history.js        # 변경 이력 (2-5)
├─ src/ui/              # 정책표, 패킷 시험, 정책 점검, 이력 화면
├─ tests/               # *.test.mjs, SPEC 3절 함정 테스트 포함
├─ package.json         # 스크립트만 (의존성 없음)
└─ index.html           # 빌드 없이 브라우저에서 바로 실행
```
- 이력과 정책표는 `localStorage` 에 보관(실패해도 동작), JSON 내보내기·가져오기 제공.
- 빌드 없음. `src/` 를 ES 모듈로 직접 로드한다(로컬은 `python3 -m http.server`, 배포는 GitHub Pages 가능). 테스트는 `node tests/run.mjs`.

## 3. 핵심 로직
1. **first-match**: 번호 오름차순으로 훑어 첫 일치 규칙에서 즉시 멈춤. 무일치는 `matched=null, deny` + 경고. 결과에 걸린 규칙과 구역 경로(출발 구역→목적 구역)를 담아 '길찾기'로 표시.
2. **covers(A,B)**: 주소(Any → 구역 → IP/CIDR 순)와 서비스(프로토콜별 포트 범위 포함)를 판단하는 공용 함수. 섀도잉·중복이 공유.
3. **섀도잉**: i 가 j 를 덮고 동작 다름. **중복**: i 가 j 를 덮고 동작 같음.
4. **기본 거부**: 마지막 규칙이 Any-Any-Any 차단인지. **syslog**: SIEM 대상 UDP 규칙에 514 포함 여부.
5. **변경 이력**: `{time(ISO8601), type, ruleNo, before, after, by}` 자동 기록. 수정은 전·후 규칙 전체, 이동은 전후 번호를 모두 기록.
   - `type` 은 add/update/delete/move. `ruleNo` 는 변경 대상의 **변경 전 번호**(추가는 새 번호).
   - 추가는 before=null, 삭제는 after=null. 이동은 before.no / after.no 가 각각 이동 전·후 번호.
   - 규칙 번호는 위치이며 변경 후 항상 1..n 으로 다시 매겨진다(밀려난 다른 규칙은 별도 이력을 남기지 않음).
   - 바뀐 것이 없는 수정과 제자리 이동은 이력을 남기지 않는다. 입력 검증에 실패한 변경은 적용도 기록도 하지 않는다.
   - 모든 변경은 `Policy` 클래스를 통해서만 일어나므로 이력이 빠지지 않는다. `snapshot()/restore()` 로 저장·복원.
6. **입력 검증**: "알 수 없는 주소", "서비스 형식 오류".

## 4. 화면
- 정책표 편집(추가·수정·삭제·위/아래 이동)
- 패킷 시험(출발 IP, 목적 IP, 프로토콜, 포트 → 걸린 규칙 하이라이트, 허용/차단, 구역 경로)
- 정책 점검 버튼(섀도잉·중복·기본 거부·syslog 경고 목록)
- 이력 탭(시간순 목록, 수정 전후 비교)
